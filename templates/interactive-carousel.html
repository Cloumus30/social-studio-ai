ARCHITECTURE 01/07

Arsitektur Microservices Kalian Sebenarnya Cuma Monolit yang Disebar Lewat Kabel.

Pernah ngerasa deploy makin ribet, latency naik drastis, tapi scalability gak nambah? Mari kita bedah akar masalahnya tanpa basa-basi.

@logikanyatech GESER
ROOT CAUSE 02/07

Kutukan Distributed Monolith di Balik HTTP Calls.

Ketika Service A harus manggil Service B secara sinkron cuma buat validasi data kasir, satu service lemot bakal ngerontokin seluruh cluster.

Failure Mode:Cascading Timeout
Network Penalty:+45ms per Hop
@logikanyatech GESER
THE SHIFT 03/07

Ubah Pola Sinkron Jadi Event-Driven Async.

Service A gak perlu nunggu jawaban. Cukup lempar status transaksi ke message log, lalu biarkan service lain mengonsumsi secara independen.

Coupling:Zero Tight Binding
Recovery:Replay Logs Anytime
@logikanyatech GESER
INFRASTRUCTURE 04/07

Investasi di Sequential Append, Bukan Lock Database.

Append-only log di NVMe disk mampu melayani ratusan ribu throughput per detik tanpa overhead row lock di database transaksi.

Write Pattern:Sequential Disk I/O
Throughput:> 150K Ops/Sec
@logikanyatech GESER
ADOPTION 05/07

Kapan Wajib Pakai & Kapan Cukup Monolit?

Kalau traffic tim kalian belum butuh deploy terpisah per squad, modular monolith selalu lebih cepat, murah, dan gampang di-debug.

Squad < 15 Dev:Tetap di Monolith
Squad > 50 Dev:Event-Driven Services
@logikanyatech GESER
COMPARISON 06/07

Komparasi: RPC Sync vs Event Streaming.

Coupling:Ketat ➔ Lepas Total
Resilience:Rentan ➔ Fault Tolerant
Debugging:Traceable ➔ Log Replay

Pilihlah arsitektur berdasarkan kendala teknis nyata di lapangan, bukan sekadar ikut tren perusahaan raksasa.
